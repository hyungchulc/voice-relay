# Video production plan

## One-demo narrative

The hero proof is mid-turn voice steering of one persistent Codex task.

Do not present Voice Relay as a general autonomous assistant, offline AI,
hands-free coding system, or stable release.

## Hero demo

Target length is `50` to `55` seconds.

| Time | Picture and action | Exact overlay |
| --- | --- | --- |
| `0-4s` | Open on a clean Mac surface with Voice Relay visible. Start the bounded task by voice. | `Start by voice.` |
| `4-14s` | Show the same dedicated Codex task accepting the request and beginning work. | `One persistent Codex task.` |
| `14-25s` | Keep the streamed progress visible. Do not hide real waiting. If time is compressed, label the speed accurately. | `See the work as it happens.` |
| `25-34s` | Speak a meaningful correction while Codex is still working. | `Speak again to steer it.` |
| `34-44s` | Show the same active task adapting to the correction and finishing. | `Same task. New direction.` |
| `44-49s` | Demonstrate Stop or Escape on a safe bounded turn. | `One stop control.` |
| `49-55s` | Use the 16:9 or vertical end card. | `Voice Relay` and `Public developer alpha` |

## Demo request

Use a bounded task whose answer is safe to show and visibly changes after a
spoken correction.

Recommended structure:

```text
Find three quiet Stockholm museums that are open tomorrow and make a short afternoon plan.
```

Mid-turn correction:

```text
Actually, keep every stop within walking distance of Moderna Museet.
```

Reverify every external fact on the filming date. If a live task would expose
location, account, private task history, or unstable web state, replace it with
a local sample repository task that has the same visible steering boundary.

## Cutdowns

### X cutdown

- `20` seconds, `16:9` or `1:1`.
- Put the spoken correction inside the first `5` seconds.
- Burn in the core overlay and upload the matching English SRT on X web.
- End on `Public developer alpha`, not `stable`, `production ready`, or
  `early access`.

### Threads cutdown

- `15` to `25` seconds, `4:5`.
- Korean burned-in captions.
- Keep the main post experience-led. Put the GitHub link and installation
  boundary in the first reply.
- Select `AI Threads` only after it is included in the approval preview.

### Reddit media

- Prefer one clean screenshot or the `20` second steering cut.
- Do not use the same launch body across communities.
- Show the developer relationship, free GPLv3 pricing, and non-notarized alpha
  boundary in the post body.

## Capture gate

Record the live demo only after all checks below pass.

- The development lane has fresh regression and live proof for the voice-turn
  boundary used in the demo.
- The exact release or build being filmed is recorded.
- The dedicated demo task contains no private history.
- Notifications, account names, local paths, IDs, and unrelated windows are
  out of frame.
- The voice transcript, Codex commentary, correction, and final result are
  legible at export size.
- Microphone and system audio are captured separately.
- Any time compression carries a visible speed label.
- The correction is received by the same active task and no duplicate local
  reply or duplicate forwarding appears.
- Stop or Escape rejects late output in the recorded take.

## Export set

- `3840x2160`, `30 fps`, `50-55s` hero master.
- `1920x1080`, `20s` X cutdown.
- `1080x1350`, `15-25s` Threads cutdown.
- `1080x1920`, `15s` vertical cutdown.
- English and Korean burned-in versions.
- English SRT for X web.
- One lossless archive master and H.264 delivery exports.

## Claims to avoid

- Hands-free coding.
- Private, secure, local AI, offline, or always listening.
- Unlimited context, autonomous completion, or background reliability.
- Stable, production ready, notarized, or ready for every Mac.
- API-key-free without the boundary. Use `no separate API-key setup`.
